# 굴착 배우기 과정 재설계 (레버 익히기 이후)

- 날짜: 2026-11-14
- 자리: `src/sim/leverDrill.ts`(본보기), `src/sim/leverSchool.ts`, `src/sim/tutorial.ts`
- 검토: 굴착기 전문 강사·현장 전문가가 초안, 냉정한 전문가·개발자·기획자가 3회 검수 (아스트라)
- **읽는 법**: 본문에는 **확인된 것만** 적는다. 틀렸다가 고친 내용은 본문에 남기지 않고
  맨 뒤 **부록. 정정 기록**에 이유만 둔다. 본문만 읽어도 틀리지 않게 하기 위함이다.
- **이 문서의 숫자 표기 규칙**: `[측정]` = 이 코드베이스에서 직접 돌려 잰 값.
  `[출처]` = 공개 자료에서 읽은 값(링크 포함). `[2차]` = 아스트라가 인용했고 내가 원문을 열어 확인하지 않은 값.
  `[가정]` = 코드를 읽은 추론일 뿐 돌려 보지 않은 것. **표기 없는 숫자는 쓰지 않는다.**
- **처음 보는 사람 검수**: 화면에 뜨는 문장만 주고 자료는 하나도 주지 않은 채 "모르는 낱말을 전부 집어내라"고 시킨다.
  전문가 검수는 이걸 못 잡는다 — 명세를 읽고 시작하므로 이미 아는 상태다. 문구를 고칠 때마다 다시 돌린다.
  **한계**: 이 검수자는 글자만 보고 화면은 못 본다. 깜빡임·노브 움직임·막대로 해결되는 지적은 걸러서 받는다.

## 0. 이 과정을 듣는 사람 (앱 주인 정의)

- **필기 시험에 합격한 사람**이다. 붐·암·버킷·선회·평적·실격 같은 **용어는 이미 안다.**
- **시험 영상을 여러 번 본 사람**이다. 작업 순서도 대충 안다.
- **레버는 잡아 본 적이 없다.** 영상으로 못 배우는 **손맛** 때문에 이 앱에 왔다.

그래서:

- 용어를 풀어 쓰느라 글자를 늘리지 않는다. **붐·암·버킷·선회는 그대로 쓴다.**
- 설명해야 하는 것은 **시험장의 자리**(A·B·C가 어디인지)와 **손맛**(레버를 얼마나·얼마나 빨리)뿐이다.
- 작업 순서 설명은 짧게. 아는 걸 또 말하면 안 읽는다.

> 초심자 검수를 돌릴 때도 이 사람으로 돌린다 — "굴착기를 한 번도 본 적 없는 사람"이 아니라
> **"필기 합격 · 영상 다수 시청 · 레버는 처음"**. 더 모르는 사람으로 돌리면 쓸데없는 지적이 섞인다.

## 1. 왜 다시 짜나

지금 배우기는 미션이 11개인데 두 가지 형식이 섞여 있다.

- **레버 익히기** — 지시 하나 → 부품 깜빡임 → 즉시 성공·실패 반응. 초보가 끝까지 간다.
- **나머지 10개** — 수치 오차를 재거나(기본기 2~5) 긴 작업을 한 번에 시킨다(기초·숙련). 잘했는지 알기 어렵고, 같은 작업이 여러 미션에 흩어져 있다.

검수 판정: **미션을 늘리지 말고 11개를 7개로 합쳐라.** 같은 작업을 또 시키면 완주 부담만 는다.

## 2. 목표

- 레버 익히기를 끝낸 사람이 **시험 과제 한 바퀴를 혼자 돌 수 있는 상태**로 만든다.
- 앱 주인의 교육 목표를 끝까지 가르친다: **부드럽게 움직이기 → 덜컹 없이 멈추기 → 동시 조작 → 동시 조작하면서 부드럽게.**
- 모든 단계가 레버 익히기와 같은 **지시 → 반응 → 피드백** 형식을 쓴다.

### 비목표
- 시험 과제 한 바퀴(4회 굴착·평탄·종료, 4분)는 배우기에 넣지 않는다. 이미 있는 **연습 시험** 모드가 그것이다. 7단계를 마치면 그리로 보낸다.
- 코스 주행은 건드리지 않는다.

### 안티목표 (이러면 실패)
- **따라치기.** 긴 작업을 레버 입력 순서로 쪼개 맞히게 하면 교육이 아니다. 구간은 *판단*이 갈리는 곳에서만 나눈다.
- 야매 요령. 시험 실격 조건과 어긋나는 편법을 가르치지 않는다.
- 안전 기준 낮추기. 초보가 어려워한다고 B 통과 여유를 늘리지 않는다.
- **아직 안 가르친 조작을 시키기.** 다만 몸통 돌리기는 예외다 — 앞 단계가 자세를 다 만들어 놓으므로
  "왼쪽 레버를 오른쪽으로"면 충분하다. 빈 버킷 연습 같은 걸 따로 만들지 않는다.

## 3. 제약

- 물리 상수는 건드리지 않는다 (교육이 쉬워지게 시뮬을 바꾸지 않는다).
- 저가폰 우선. 새 렌더 패스·흐림 효과 금지.
- 모든 판정은 엔진이 실제로 재는 값으로만 한다.
- **흙 작업 중에는 `goHome` 순간이동을 쓰지 않는다.** `[가정]` `teleport`는 자세를 바로 바꾸므로
  그 사이 프레임의 흙 깎기·충돌이 계산되지 않는다 (코드를 읽은 추론이며 돌려 보지는 않았다).
  레버 익히기는 흙을 안 건드리므로 그대로 둔다.

## 4. 접근 (셋 중 하나를 골랐다)

| 안 | 내용 | 판정 |
|---|---|---|
| A. 기존 11개 두고 새 과정 추가 | 안전하지만 미션 18개 | **버림** — 초보가 어디부터 할지 모른다 |
| B. 형식만 통일 | 작업량 최소 | **버림** — 중복과 순서 문제가 남는다 |
| **C. 7개로 합쳐 새로 만든다** | 기존 11개 삭제, 레버 익히기 형식으로 재작성 | **채택** (앱 주인 결정) |

## 5. 커리큘럼

순서는 앱 주인이 정했다: **멈춘 상태의 기술(퍼기·쏟기)을 먼저, 그 사이를 잇는 옮겨 가는 동작을 따로, 마지막에 전부 연결.**

| # | 제목 | 여기서만 배우는 것 |
|---|---|---|
| 1 | 레버 익히기 | 레버 방향과 부품 이름 (지금 것 그대로) |
| 2 | 흙 퍼기 | 제자리에서 한 삽. 얕게 물고 당기며 오므리기 |
| 3 | 퍼기 준비 자세 만들기 | 동시 조작에 **이름을 붙여** 가르친다. 뻗으면서 내리고 열기 |
| 4 | 쏟고 돌릴 자세 만들기 | 버리는 자리에 쏟고, 가로줄 위 안전 자세로 되돌리기 |
| 5 | 한 바퀴 연결 | 퍼기 → 선회 → 쏟기 → 복귀. **선회와 장애물 통과를 처음 다룬다** |
| 6 | 깊어진 구덩이 파기 | 먼 쪽 흙, 파도 되는 끝선 안에서 |
| 7 | 평탄·종료 | 흙에 댄 채 왕복, 버킷 펴서 내려놓기 |

마치면 **연습 시험**으로 보낸다.

## 5-2. 실측값 (명세의 숫자는 여기서 나왔다)

적어 놓고 안 재본 숫자가 지난번에 사고를 냈으므로, **쓰기 전에 전부 돌려 봤다.**

모두 `[측정]`. 적재량은 **내가 쓴 정석 조작 스크립트** 기준이며, 더 잘 파면 더 담길 수 있다.

|---|---|
| 정석대로 한 번 퍼 담기 | **0.90·SC** (안쪽 비율 0.67) |

| 암 당기다 반대로 꺾기 | maxJolt **0.216** |

> **붐 각도 `[측정]`.** 앞 주인은 "실제는 붐을 80~90°로 세운다"고 했고, 우리 붐은 이미 그렇다.
> 외곽선이 구스넥(굽은) 모양이라 **중심선이 36% 지점에서 0.48m 올라간다**.
> 붐을 끝까지 올리면(핀-핀 직선 67°) — 붐 **아랫부분 84.5°** · 윗부분 **57.2°**.
> 운전석에서 보이는 것은 아랫부분이므로 80~90°가 맞다.
> `pose.boom`의 67°는 기구학용 핀-핀 각도일 뿐, 화면에 보이는 각이 아니다 — 둔 것을 헷갈리지 말 것.

### 이 숫자가 바꾼 것 넷

1. **적재량 기준을 낮춘다.** 정석이 0.90인데 통과를 0.8로 잡으면 정석과 거의 같다 — 초보는 못 넘는다.
   → **담기 통과 ≥0.6·SC, 들고 나서 ≥0.5·SC.** 0.75 이상은 별점으로.
2. **붐으로는 "덜컹 없이 멈추기"를 가르칠 수 없다.** 확 놓아도 0.005다 (유압 감쇠가 먹는다).
   덜컹은 **선회**에서만 난다 (놓기 0.111 > 경고 0.1, 반대꺾음 0.293 > 흘림 0.18).
   → **덜컹 교육은 5단계 선회로 옮긴다.** 2-④에 덜컹 조건을 걸면 무조건 통과하는 가짜 관문이 된다.
   → 교육용 임계는 경고선(0.1)이 아니라 **구간 maxJolt < 0.06**으로 따로 둔다.
3. **드는 방식에 따라 흙이 남는 양이 다르다** `[측정]`. 2단계를 실제로 돌려 다시 쟀다.

| 드는 방식 | 담았던 양 대비 유지 |
|---|---|
| 오므리면서 들기 | **67%** |
| 안 오므리고 그냥 들기 | **0%** (다 쏟는다) |
| 먼저 끝까지 오므린 뒤에 들기 | **불가능** — 흙이 가득 차면 버킷이 +23°에서 막힌다 |

   → 2단계는 **"오므리면서 들어 올리기"**를 가르친다. 동시 조작에 **이름을 붙이는 것은 3단계**다.
   (앞서 "오므리며 들면 82%, 따로 하면 34%"라고 적었던 것은 2단계 밖에서 다른 조건으로 잰 값이었다.)
4. **2-①의 "이빨 수평"은 쓸 반경에서 먼저 재야 한다** `[측정]`.
   수평 자세는 굴착구역·지면 부근에 **1522개** 있지만 **반경 7m 부근에 몰려** 있고
   (예: 붐 11° 암 −79° 버킷 68°), 가까운 반경(4.8~6.2m)에서는 못 찾았다.
   빌더: 구간마다 도달 가능성 테스트를 먼저 쓸 것.

**암을 중간만 뻗고 버킷을 적당히 오므리면 된다** — 암을 다 뻗으면 실격선에 닿으므로 실제 조작과도 맞는다.

이빨 수평은 가까운 반경(4.8~6.2m)에서는 못 찾았다. 구간 목표로 쓰려면 **쓸 반경에서 먼저 재야 한다.**

### 덤으로 확인한 것

- `fill(s, ratio)`로 넣은 흙은 **버킷이 충분히 오므려져 있으면 유지된다** (−90°에서 100%).
  4단계 "흙을 담고 시작"을 이 방법으로 만들어도 된다. 단 **오므림을 먼저 맞춰 놓아야** 한다.
- 레버 양과 속도는 거의 비례한다. **1칸(0.15~0.40)은 3~10°/s, 3칸(0.7~1.0)은 17~24°/s** — 2~5배 차이라 눈에 띈다. 3칸 설계는 유효하다.

### 각 단계의 구간·지시문·통과 조건

`SC` = 버킷 평적 용량. 판정은 **자세를 만든 뒤 잠깐 멈춘 상태**에서 한다.

**2. 흙 퍼기**
1. "버킷 이빨을 파는 자리에 맞추세요" (땅에 목표 자리 표시) — A 방향, 이빨이 목표 반경 ±0.4m, 지면 위 5~35cm.
   **버킷 각은 쓸 반경에서 실측해 정한다** (5-2 참고)
2. "붐을 내려 이빨을 흙에 넣으세요" — 파는 자리 안에서 `groundGap < −0.15m`, 바닥 충격 0회
3. "버킷을 오므리며 암을 당겨 채우세요" — 적재량 ≥ **0.6·SC**, 과부하·차체 들림 없음
4. "오므리면서 붐을 올리세요" — 이빨 높이 > 0.8m, 적재량 ≥ **0.5·SC**. **덜컹 조건 없음**(붐은 덜컹이 안 난다).
   여기서 동시 조작을 **몸으로 먼저 겪는다** — 따로 오므리고 들면 34%만 남고, 같이 하면 82%가 남는다

**3. 퍼기 준비 자세 만들기** (엔진이 파는 자리로 돌아와 높이 든 상태로 시작시킨다. 몸통 돌리기는 안 시킨다)
1. "버킷을 높이 든 채 암을 펴세요" — 파는 자리 방향 유지, 버킷 최저점이 가로줄보다 ≥0.3m 위
2. "붐을 내리면서 암을 펴고 버킷을 여세요" — **목표 관절 2개 이상이 같이 움직인 시간 ≥ 30%**
3. "이빨을 파는 자리 위에서 부드럽게 멈추세요" — 2-①의 자세로 0.2초 유지, 덜컹 0회

**4. 쏟고 돌릴 자세 만들기** (흙을 담고 버리는 자리에 온 상태로 시작)
1. "버리는 자리 위에서 버킷을 천천히 여세요" — 그 구덩이 안에서 적재량 < 0.1·SC, 구덩이 밖 유출 없음
2. "버킷을 오므리면서 암을 당기세요" — 오므림 ≥60°, 버킷이 장애물 기둥 둘에서 각각 0.3m 여유
3. "붐을 올려 가로줄 위에서 멈추세요" — 버킷 최저점 ≥ 가로줄+0.3m, 0.2초 유지, 덜컹 0회

**5. 한 바퀴 연결** (몸통 돌리기는 **따로 안 가르친다**. 앞 단계에서 자세를 다 잡아 놨으므로 좌우로 밀면 끝이다)
1. "파는 자리에서 한 번 퍼 담으세요" — 적재량 ≥ **0.5·SC**, 오므림 충분
2. "암을 당기며 붐을 올려 선회 자세로" — `readyToCarry`, 동시 비율 ≥30%, 덜컹 0회
3. "왼쪽 레버를 오른쪽으로 — 버리는 자리까지" — 통과 중 D-PASS·D-POLE 0회, 도착 적재량 ≥ 0.5·SC, 정지 덜컹 0회
4. "쏟고 다시 선회 자세로" — 4단계 조건과 같음
5. "왼쪽 레버를 왼쪽으로 — 파는 자리에서 멈추세요" — 역방향 통과, 파는 자리 방향 ±8°에서 정지, 덜컹 0회

**6. 깊어진 구덩이 파기**
1. "이빨을 세워 먼 쪽 흙까지 뻗으세요" — 버킷 최원점이 파도 되는 끝선 안쪽 0.08~0.4m, 이빨 수직 오차 ≤20°
2. "붐을 내려 이빨을 깊이 넣으세요" — `groundGap < −0.15m`, 충격·끝선 위반 0회
3. "오므리며 당기다 붐을 올리세요" — 적재량 ≥ **0.6·SC**, 끝날 때 오므림 충분·적재량 ≥ **0.5·SC**

**7. 평탄·종료**
1. "버킷을 펴서 흙더미 너머로 뻗으세요" — 최대 펼침 15° 이내, 이빨 반경 ≥ 버리는 자리 바깥끝−0.4m
2. "흙에 대고 암을 당기며 붐을 살짝 올리세요" — 접촉 상태 안쪽 이동 ≥0.8m
3. "암과 붐을 함께 밀어 고르세요" — 접촉 바깥쪽 이동 ≥1.0m, 평탄 토량 ≥0.03㎥, 동시 비율 ≥30%
4. "버킷을 펴서 내려놓고 완전히 멈추세요" — 버리는 자리의 고른 면, 종료 높이·각도 충족, 모든 관절 <2°/s로 1초

## 6. 엔진에 더해야 하는 것

1. **동시 동작 비율** — 구간 안에서 `|vel[j]| > 임계`인 목표 관절이 2개 이상인 프레임 / 전체 프레임. 미션 쪽(`mem`)에서 센다.
2. **구간 maxJolt** — 교육용 임계 0.06. 엔진의 `W-JOLT`(0.1)는 선회 놓기(0.111)에서야 뜬다 `[측정]`.
   구간 시작에 `s.maxJolt = 0`으로 초기화하고 구간 끝에 읽는다.
   **출발의 부드러움은 엔진이 전혀 안 잡는다** — 0에서 끝까지 즉시 밀어도 maxJolt 0.000 `[측정]`.
   그래서 출발은 **3칸 표시**로만 가르치고 덜컹으로 채점하지 않는다.
3. **구간 이벤트 기록** — 그 구간 동안 일어난 D-PASS·D-POLE·과부하·차체 들림. `mem`에 프레임마다 쌓는다.
4. `readyToCarry`(이미 `tutorial.ts`에 있음, private)를 내보내 5단계에서 쓴다.
5. **데모 입력** — 앱이 레버를 대신 움직인다. `session.input`은 `main.ts` 한 곳에서 만들어지므로
   (`src/main.ts`의 `session.input = {...}`) 튜토리얼이 켜면 그 값을 대신 쓰고, 화면 조이스틱 손잡이도
   같은 값으로 움직인다.
6. **카메라 이동 연출** — 1.5초 동안 목표를 보여주고 되돌아온다. 화면을 누르면 건너뛴다.
7. **땅 표식** — 목표 자리 테두리와 이빨 맞출 점. 단순 도형, 새 렌더 패스 없음.
8. **유효 굴착 횟수를 쓰지 않는다** — `digCount`는 A를 벗어날 때 확정되므로 "퍼 담은 순간 1회"로 쓰면 틀린다. 2·6단계는 적재량으로 판정한다.

흙 작업 중에는 순간이동하지 않는다. 대신 지금 자세에 맞는 실제 조작을 **한 번에 하나씩** 시킨다:

> 버킷 닫기 → 붐 들어 흙·장애물에서 빼기 → 암으로 안전 반경 맞추기 → 목적 방향으로 선회 → 그 구간 다시

흙을 흘렸거나 덜 담았으면 **바뀐 지형을 그대로 둔 채** 다시 파게 한다. 자세 배치(`teleport`)는 **단계에 들어올 때만** 쓴다.

## 7-2. 장소와 용어를 어떻게 알려 주나

초보는 **A·B·C가 뭔지 모른다.** 지금 3D 라벨은 글자 "A" "B" "C"뿐이고, 어디에도 뜻이 없다.
붐·암 때와 같은 문제이므로 같은 방법으로 푼다.

1. **지시문에 시험 도면 글자를 쓰지 않는다.** 아래 이름으로 말한다.
2. **처음 가리킬 때 그 자리가 깜빡이고 이름이 뜬다** — 부품과 똑같이 `#dr-part`에 `깜빡이는 곳 = 파는 자리`.
3. **3D 라벨에 뜻을 붙인다**: `A` → `A 파는 자리`, `B` → `B 장애물`, `C` → `C 버리는 자리`.
   시험 도면 글자는 남긴다 (실기장에서 그렇게 부르므로 아예 안 알려주면 안 된다).

| 시험 도면 용어 | 화면에서 부르는 이름 |
|---|---|
| A지점 | 파는 자리 |
| B지점 | 장애물 |
| C지점 | 버리는 자리 |
| 장애물선 (줄) | 가로줄 |
| 폴 | 기둥 |
| 가상굴착제한선 | 파도 되는 끝선 |
| 오버스윙제한선 | 넘어가면 안 되는 선 |
### 동작 이름과 레버를 계속 이어 준다

1단계는 **레버 말**로 지시한다 ("오른쪽 레버를 아래로"). 2단계부터는 **동작 말**로 바뀐다
("암을 당겨", "버킷을 오므리며"). 초보는 아직 그 둘을 못 잇는다. 끊기면 2단계 첫 지시에서 앱을 끈다.

그래서 **2~4단계에서는 부품 이름 줄에 레버 방향을 같이 적는다.** 새 화면은 필요 없다.

> 암을 당겨 흙을 채우세요
> `깜빡이는 곳 = 암 · 왼쪽 레버 아래`

5단계부터 뗀다 (세 단계 동안 썼으면 익었다).

### 장소는 이름만으로 부족하다

"파는 자리"가 **어디인지·어디까지인지** 모른다. 그래서:

- 그 자리를 처음 가리킬 때 **3D에서 그 구역이 깜빡인다** (부품과 같은 방식)
- 2단계 ①처럼 목표 지점이 있는 구간은 **땅에 목표 자리를 표시한다** (이빨을 맞출 곳)

### 처음 쓰는 말은 반드시 깜빡임과 함께

부품 이름과 똑같이, **처음 나오는 말은 그 자리를 깜빡이고 이름을 준다.** 초심자 검수에서 걸린 것들:

**필기 합격자이므로 붐·암·버킷·선회·이빨·평적은 그대로 쓴다.** 손봐야 하는 건 자리와 손맛뿐이다.

| 말 | 어떻게 |
|---|---|
| A·B·C | **자리 이름으로 바꾼다** (파는 자리·장애물·버리는 자리). 처음 가리킬 때 그 구역이 깜빡인다 |
| 표시 | 땅의 표식이 깜빡이며 `깜빡이는 곳 = 파기 시작점` |
| 조금·천천히·살짝 | **3칸 표시와 시범으로 보여준다.** 글자로 설명하지 않는다 |
| 중립 | "레버를 가운데로" (뜻은 알지만 손이 더 분명해진다) |

### 모호한 부사에 기준을 준다

"천천히 · 부드럽게 · 살짝 · 완전히"는 초보에게 아무 뜻이 없다. 쓰는 곳마다 기준을 같이 준다.

- "천천히 들어 멈추세요" → 반응 줄에 `덜컹 없이 멈췄습니다` / `덜컹했습니다 — 레버를 천천히 중립으로`
- "완전히 멈추세요" → 멈춤이 인정되는 동안 표시가 차오른다
- 애매하면 **동작으로 바꿔 쓴다**: "살짝 올리세요" → "한 칸만 올리세요"

### 구간마다 왜 하는지 한 줄

성공 반응 줄(`#dr-say`)은 지금 "붐이 올라갑니다"처럼 **무슨 일이 일어났는지**만 말한다.
2단계부터는 **왜 그렇게 하는지**를 같이 말한다.

> "높이 들었습니다 — 이 높이라야 가로줄에 안 걸립니다"

## 7-3. 정보량 상한

UI/UX·쇼핑앱 디자이너·가오레 AD 판정. 길어지면 안 읽는다.

- **한 순간 최대 28자, 2줄.** 공백·부호 포함.
- **`#dr-text`는 14자 이내 한 줄.**
- **세 줄을 동시에 띄우지 않는다.**
  - 조작 중: `#dr-text` + `#dr-part`. `#dr-say`는 감춘다.
  - 성공·실패 직후: 조작 안내를 치우고 `#dr-text` + `#dr-say`로 반응만.
- **'왜'를 글자로 쓰는 경우**: 다음 조작을 바꾸는 규칙일 때만. 예) "중립으로 천천히"
- **'왜'를 장면으로 보여주는 경우**: 높이·거리·속도처럼 눈으로 비교되는 것. 가로줄과 버킷 사이 여유,
  목표 자리, 레버 이동량을 **보여주고 문장은 안 쓴다.**

## 7-4. 손맛 시범 — 레버를 얼마나 미는가

이 앱 유저는 **시험 영상을 이미 본 사람들**이다. 작업 순서는 알고, 영상으로 못 배우는 손맛 때문에 온다.
"천천히·부드럽게"는 뜻을 알아도 **레버를 어떻게 움직이라는 건지** 모른다. 그래서 **앱이 먼저 해 보인다.**

**2단계 첫 조작 직전, 시범 3회.** 별도 단계로 빼지 않는다.

| | 보여주는 것 | 글자 |
|---|---|---|
| 1 | 붐을 올리는데 레버를 **¼만** 밀어 느리게 | "이만큼만 미세요" |
| 2 | 자세를 되돌리고 레버를 **끝까지** 밀어 빠르게 | "끝까지 미세요" |
| 3 | ¼로 움직이다 **서서히 가운데로** 가져와 덜컹 없이 멈춤 | "레버를 가운데로 천천히" |

- 시범 중 **화면의 조이스틱 손잡이가 실제로 움직인다.** 손잡이 경로에 ¼·끝 위치만 표시.
- 두 장면을 나란히 놓지 않는다. 같은 화면에서 **연속 비교**.
- 시범 뒤 "같이 해보세요" — 짧게 출발하고 멈추게 한다.
- 급히 밀거나 놓으면 **그 구간만 한 번 더 시범** 보이고 바로 다시.

## 7-5. 파는 자리 보여주기

땅을 파기 전에 **카메라가 흙 쪽으로 간다.**

- **1.5초** 동안 이동, 마지막 0.3초는 멈춰서 보게 한다. **화면을 누르면 즉시 건너뛴다.**
- 땅에 **얇은 테두리 + 이빨을 맞출 작은 표식**만. 파면 안 되는 경계는 다른 색 실선.
  새 렌더 효과 없이 기존 장면의 단순 도형으로 그린다 (저가폰).
- 이동 중 글자는 **한 줄**: "여기가 파는 자리"
- **"가장자리에서 30cm 안쪽" 같은 수치는 `판정명세_굴착.md`의 실제 판정 기준과 맞을 때만 쓴다.**
  맞춰 보고 다르면 수치를 빼거나 기준에 맞게 고친다. (빌더가 확인할 것)

## 7-6. 2단계 '흙 퍼기' 한 판 — 화면 단위

다른 단계도 이 틀을 따른다.

1. 빈 버킷, 실제 시험장. **"한 번 퍼 담아보세요"**
2. 손맛 시범 3회 — 손잡이와 붐이 같이 움직임. **"이만큼만 미세요" → "끝까지 미세요" → "레버를 가운데로 천천히"**
3. 유저가 짧게 출발·정지. 되면 체크 + **"부드럽게 멈췄어요"**
4. 카메라가 흙으로 이동. 테두리·표식. **"여기가 파는 자리"**
5. **"이빨을 표시에 맞추세요"** — 맞으면 표식이 초록으로
6. **"이빨을 흙에 넣으세요"** — 충격 나면 **"조금만 밀어보세요"**
7. **"버킷 오므리며 암 당기기"** — 부품 줄에 레버 둘을 같이. 흙이 차는 모습으로 양을 보여줌
8. **"붐을 올려 가운데로 천천히"** — 높이 표식에 닿고 덜컹 없이 멈추면 체크
9. 담긴 버킷을 잠깐 보여주고 **"한 번 성공!"** → 결과 화면

## 7-7. 레버를 얼마나 밀고 있는지 보여주기

앱 주인 지적: **"¼만 밀고 있다는 걸 뭘로 확인시켜 주나"**, **"인디케이터가 작아서 손에 가린다"**,
그리고 **"더 쉽고 직관적인 방법을 찾아봐"**.

디자이너 3인이 안을 다섯 개 놓고 비교한 결과, **스틱 위 카드·막대·퍼센트는 전부 버렸다.**

| 버린 안 | 치명적 단점 |
|---|---|
| 스틱 위 상태 카드 + 막대 | 읽어야 한다. 조작 중엔 안 읽는다 |
| 유령 노브 (목표 위치에 반투명 노브) | '조금'의 목표는 중심에서 **20px** — 엄지가 덮는 **75px** 안이다 `[2차]` |
| 스틱 링 게이지 | 엄지는 피하지만 시선이 화면 가운데라 놓친다 |
| 표시 없이 장비 속도로 | 가속을 기다려야 해서 '지금 얼마나 밀었나'를 즉시 모른다 |
| 소리·진동 | 끄면 못 받는다 |

### 채택: 가운데 3칸

**지시문 바로 아래에 칸 3개.** 눈이 이미 가 있는 곳이고, 1칸과 3칸의 차이는 글자 없이 보인다.

```
        이만큼만 미세요          ← #dr-text
        ▮ ▯ ▯                   ← 3칸. 지금 1칸
```

- 칸 하나 **8×18px**, 간격 **4px**. (작으면 키운다 — **빌더가 실제 화면을 찍어 확인할 것**)
- `[측정]` 데드존 0.15는 `joystick.ts`의 `dz = 0.15`, 그 뒤 `main.ts`가 `curve()`를 한 번 더 건다.
- **0.15 이하 = 0칸** (데드존, 기계가 안 움직임) · **0.15~0.40 = 1칸 초록** ·
  **0.40~0.70 = 2칸 노랑** · **0.70~1.00 = 3칸 주황**
- 입력이 바뀌면 즉시 바뀐다. 흐림 효과 없음.
- **목표 칸에는 테두리**를 둔다. 거기 맞추면 그 칸이 초록으로 차고 체크.
- **읽을 글자 0자.** 조금 밀어 1칸, 끝까지 밀어 3칸 — 직접 밀어 보며 **1~2초** 안에 안다.
- 퍼센트 숫자는 쓰지 않는다 (초심자 검수: "무엇의 25%인지 모르겠다").
- 값은 **기계에 들어가는 값**이다. `joystick.ts` 데드존 0.15 + `main.ts`의 `curve()`를 거친 뒤.

### 방향 이름은 가운데 줄이 맡는다

`.lab.hint`(13px 알약, `scale 1.15` + 5px 그림자)의 확대 반짝임은 **끈다.**
손 옆에서 키워 봐야 엄지에 가리는 건 그대로다. 방향은 이미 `#dr-part`가 말한다:
`깜빡이는 곳 = 붐 · 오른쪽 레버 아래`. 스틱 둘레 라벨은 **보조 표기**로만 남긴다.

### 엄지 가림 영역 — 여기엔 읽을 것을 두지 않는다

412×892 기준 **y ≥ 665px**(화면 아래 25%)의 좌우 스틱 폭. `[2차]` 디자이너 패널 추정값이며,
계획서 Task 2-4에서 헤드리스 크롬으로 찍어 확인한다.
지시·목표·수치·성공 판정을 여기 두지 않는다. 만져야 하는 조작물(스틱)만 예외.

### 시범 중이라는 표시

**3칸은 시범에도 똑같이 쓴다** — 시범과 직접 조작의 표시가 달라지면 배운 걸 못 옮긴다.
구분은 이것만:

| | 시범(앱이 민다) | 직접(유저가 민다) |
|---|---|---|
| 노브 | 흰색 속 빈 원 | 평소 노브 |
| 배지 | `시범 중` 14px | `직접 해보기` |

시범 값은 유저 입력으로 기록하지 않는다. 시범이 끝나면 노브를 가운데로 되돌리고 **0.5초 정지** 뒤 배지를 바꾼다.

## 7-8. 시점은 운전석 (앱 주인 결정)

2~7단계 모두 **운전석 시점**이다. 실제 시험이 그렇고, 손맛을 배우는 자리도 거기다.

**따라오는 문제**: 운전석에서는 붐이 머리 위라 **깜빡여도 안 보인다.** 그래서:

- **2~7단계에서는 부품을 깜빡이지 않는다.** 필기 합격자는 붐·암·버킷이 뭔지 안다. 깜빡일 이유가 없다.
- 깜빡이는 것은 **운전석에서 보이는 것만**: 땅의 표식, 가로줄, 버킷, 흙더미.
- 부품 줄(`#dr-part`)은 **레버 방향**을 맡는다: `암 · 왼쪽 레버 아래`.
- 깜빡임은 **1단계의 핵심 장치로 남긴다** (거기서는 레버와 부품을 잇는 게 과제다).

카메라를 흙 쪽으로 1.5초 옮기는 연출(7-5)은 **운전석 안에서 시선만 내리는 것**으로 한다.
차 밖으로 나가지 않는다.

## 7-9. 기존 진행도는 초기화한다 (앱 주인 결정)

미션 id가 전부 바뀌므로 **완료 기록을 비운다.** 11개를 깬 사람도 0/7에서 시작한다.
`loadCleared()`가 이미 없는 id를 걸러내므로 크래시는 없지만, **낡은 기록을 남겨 두지 않고 지운다.**
안내 한 줄: "과정이 새로 바뀌었습니다".

## 8. 화면 (레버 익히기 것을 그대로 쓴다)

- 가운데 큰 지시문(`#dr-text`) + 부품 이름 줄(`#dr-part`) + 반응·코치 줄(`#dr-say`)
- 지시가 가리키는 부품 깜빡임, 해낼 때까지 유지
- 성공: 체크 + 원형 퍼짐 + 꽃가루 + 소리. 실패: 빨강 + 흔들림
- 시작 전 '왜 이걸 배우나' 카드, 끝나고 별 3개 + 한 줄 총평
- 2~7단계는 **튜토리얼 공간을 쓰지 않는다.** 실제 시험장(펜스·폴·줄)이 있어야 B 통과와 선을 배운다. `flat`은 1단계만.

## 9. 빌더에게 남기는 것

- 구간별 코치 문구의 정확한 말씨 (명세의 지시문은 뜻이고, 짧게 다듬어 쓴다)
- 각 단계 '왜 배우나' 카드 4줄
- 별 3개 기준선 (덜컹 횟수·동시 비율로)
- 기존 11개 미션 파일을 지우는 순서와 `fixTips`·저장된 진행도 처리
- 3D 라벨 글씨가 길어지므로(`A 파는 자리`) 스프라이트 크기·가독성 확인
